# Наши точки правок в форке (для подтягивания upstream)

Цель: форк должен оставаться совместимым с оригиналом, чтобы новые функции оригинала можно было внедрять.
Правило: **новые файлы вместо правки чужих**, а обязательные правки существующих файлов — точечные и перечислены здесь.

## Где наши изменения
| Область | Путь | Тип |
|---|---|---|
| Плагин (память, скиллы, диспетчер, аудит, планировщик) | `plugins/dsh-tool-agent-kit/` | новые файлы, чужой код не трогаем |
| Вложение плагина в сборку | `ci/install-agent-kit.mjs`, вызов из `ci/prepare-devhome.sh` | новый файл + 2 строки в CI-скрипте |
| CI сборки | `.github/workflows/build-plus.yml` | наш файл |
| Канал обновлений | `.github/workflows/release-plus.yml` | наш файл |
| Идентификатор пакета и клон рядом с оригиналом | `ci/prepare-devhome.sh`, `android-app/` | правки, см. ниже |

## Как подтягивать upstream
1. `git fetch upstream` → `git merge upstream/main` в ветке `plus`; конфликты ожидаются только в файлах из таблицы выше.
2. Если upstream обновил payload или версию APK — обновить `UPSTREAM_APK` в обоих workflow-файлах и `versionName` при необходимости.
3. Прогнать CI (`build-plus`): красный прогон = не переносим.
4. Проверить, что наш плагин попал в сборку: в логе шага «Подготовить devhome» должна быть строка
   `плагин dsh-tool-agent-kit вложен в профилей: N` (N ≥ 1).
5. Проверить, что настройки и плагины не сносятся обновлением (приложение с v1.15.8 сливает профиль, а не перезаписывает).

## Особенности сборки в CI
- `build.sh` запускается через **bash** (в нём `source`, которого нет в `dash`) — иначе шаг сборки падает с `exit 127`.
- Плагин вкладывается шагом `ci/install-agent-kit.mjs`; профиль определяется по `profiles/*/package.json`, каталог `node_modules` создаётся при необходимости.

## Чего нельзя делать
- Править официальные `dsh-tool-*` внутри payload: приложение перезаписывает их из APK.
- Менять идентификатор пакета без переноса данных (`com.deepseek.harness` ↔ `com.deepseek.harness.plus`).
- Публиковать релиз с другим ключом подписи: обновление не встанет поверх установленной версии.
- Коммитить секреты: CI отдельно проверяет payload на `sk-...` и `.credentials.yaml`.
